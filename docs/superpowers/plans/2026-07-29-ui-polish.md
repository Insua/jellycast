# 播放页可读性、首页布局与服务器管理 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` 逐任务实现。步骤用 checkbox(`- [ ]`)跟踪。

**Goal:** 当前字幕行任何时刻都完整可见;首页顶部没有多余空白;能下拉刷新;能删服务器。

**Architecture:** 四个改动模块不相交(`:feature:player` / `:feature:home` + `:feature:library` / `:feature:server`),可并发。布局类问题**必须有真机截图为证** —— 单测测不出来。

**Tech Stack:** Kotlin · Compose · Material 3 · Room · DataStore · JUnit5 + MockK(JVM)· JUnit4 + AndroidJUnit4(仪器)

## Global Constraints

- 设计文档:`docs/superpowers/specs/2026-07-29-ui-polish-design.md` —— 需求以它为准。
- 🔴 **主题保持浅色。** 用户已多次明确否决深色。
- 🔴 **播放页仍是大封面 + 歌词式字幕,不引入视频画面。** 但**当前行完整可见优先于封面尺寸**。
- 🔴 **布局问题必须真机截图为证。** 本项目已有先例:v3 的离线提示条"存在但被 LazyColumn 挤出可视区",
  Compose 测试全绿却在真机上看不见。断言要用 `assertIsDisplayed()` 而非 `assertExists()`。
- 🔴 **凭据铁律:** 真实服务器地址、用户名、密码不得出现在代码、测试、文档、提交信息、日志或报告中。
  **提交信息与报告里也不得出现用户的剧名。**
- **禁止凭记忆写 Jellyfin API。** 用 `jq` 核对 `docs/jellyfin-openapi.json`。**Jellyfin 对错误大小写的
  查询参数静默忽略**,已查出过 6 处。
- **永远不渲染视频**:不引入 `media3-ui`、不建 `PlayerView`、不绑 `Surface`。
- **网络不可用绝不允许崩溃。**
- **ticks 只在网络映射层换算一次。**
- 不得削弱既有保证:seek 走重新 resolve / 最新 seek 胜出且过期结果不置错误态 / 前台服务进入不依赖网络延迟 /
  L1 探测按 mediaSource 缓存 / 无路径把会话钉死在 L3 / 字幕失败降级为空且捕获 `Throwable` 并重抛
  `CancellationException` / 弹幕轨不作为默认字幕 / `indexAt` 取"覆盖当前位置且最晚开始"的一条 /
  歌词轮询睡到下一边界(80–500ms 夹取)/ 排序筛选参与缓存 bucket 键 / 点某集把整季作为队列传出 /
  首页各分区并发加载且互不影响 / 离线横幅按分区 OR。
- 版本走 `gradle/libs.versions.toml` 别名,**不写死**。
- **AGP 9 内置 Kotlin:绝不 apply `org.jetbrains.kotlin.android`;没有 `kotlinOptions { }`。**
- 源集:`src/test/` = JUnit5 + MockK;`src/androidTest/` = JUnit4 + AndroidJUnit4。**不混用。**
- TDD:先写测试、跑、**确认失败**、再实现。
- 跑 gradle 带 `--no-daemon`。**模拟器只有一台,需要仪器测试的任务必须串行。**
- 每个 Task 结束 commit,Conventional Commits。

**Files:**

**根因(已从源码确认):** `PlayerScreen` 是自上而下的 `Column`,歌词区拿 `Modifier.weight(1f)` ——

控制行、工具栏之后,只剩约两行高度。再叠加 `LyricsView` 的
`contentPadding = PaddingValues(vertical = halfViewport)`(上下各垫半个视口),
可视区进一步塌缩,当前行落在边缘被裁。

- [ ] **Step 1: 先写会失败的真机测试**

`:feature:player` 目前**没有 androidTest 源集**,需新建并配 `testInstrumentationRunner`
(参考 `core/designsystem/build.gradle.kts`)。

测试内容:给定一段字幕与一个播放位置,断言**当前行完整可见** ——
用 `assertIsDisplayed()`,并进一步断言其上下**各至少有一行可见**。
用 `testTag` 定位,不要靠文案。

**自行选择并说明理由**,但必须同时满足:

  这是"感觉像播客"的关键)—— **不得为了歌词把封面砍没**

同时检查 `contentPadding = halfViewport` 在矮视口下是否仍合理。

### Task 5:剧集的自动连播必须跟着剧走,不是跟着队列走

**用户新增需求(2026-07-29)。** 现状是错的:自动连播先取当前队列的下一项,队列耗尽才去问
`NextUp`。而 v4 把首页各分区的**整行列表**当成了播放队列 —— 于是从「继续收听」点开一集剧,
播完会跳到那一行里的**另一部剧**,而不是本剧的下一集。

**正确语义:**

| 当前条目 | 播完之后 |
|---|---|
| 剧集,本季还有下一集 | 播**本剧本季的下一集** |
| 剧集,本季已完 | 播**本剧下一季的第一集** |
| 剧集,全剧所有季所有集都播完 | 停止播放,回到首页,提示「已播放完」 |
| 电影 | 停止播放,回到首页 |

**Files:**
- Modify: `core/player/src/main/java/dev/insua/jellycast/player/AutoPlayNextController.kt`
- Modify: 队列构造处(`app/.../JellyCastNavHost.kt`、`AppSessionViewModel`)
- Test: `core/player/src/test/...`

**Interfaces:** 需要按剧集顺序取下一集的能力。`JellyfinApi` 已有
`seasons(seriesId, userId)` 与 `episodes(seriesId, seasonId, userId)`,
**先用 `jq` 核对参数名与大小写再用** —— Jellyfin 对错误大小写静默忽略,项目已查出过 6 处。

- [ ] **Step 1: 写失败的测试(纯 JVM,用 MockK 假 api)**

- 本季还有下一集 → 返回该集
- 本季最后一集 → 返回**下一季第一集**(需跨季查询)
- 全剧最后一集 → 返回 null,并发出"全部播放完毕"的信号
- 电影播完 → 返回 null,发出结束信号(**不去 NextUp 找别的东西接着放**)
- **从首页分区点开的剧集,播完接的是本剧下一集,而不是该分区列表里的下一项**
  —— 这条直接对应用户报告的问题,必须有测试
- 跨季/跨剧查询失败时**不得崩溃**,静默停止即可(网络不可用绝不允许崩溃)

- [ ] **Step 2: 跑确认失败 → 实现 → 确认通过**

实现要点:
- 判断当前条目是剧集还是电影,用 `MediaItem.kind`
- 剧集:先在本季集列表里找下一集;没有则取下一季的第一集
- **保留既有保证**:自动连播只 `resolve()` 一次(v2 修过重复解析);
  「播完本集」睡眠定时被 arm 时**不得继续连播**(v1.1 的行为,有测试守着);
  引擎状态在切集后必须同步(v2 修过,否则锁屏 seek 会指向上一集)

- [ ] **Step 3: 播放结束后回到首页并提示**

需要一个从播放层传到 UI 层的"播放序列结束"信号。**不要在 `:core:player` 里直接操作导航** ——
该模块不认识导航(设计文档 §5 的边界原则)。用可观察状态,由 `:app` 的导航层消费。

提示文案:剧集全部播完提示「已播放完」;电影播完直接回首页,不必额外提示。

- [ ] **Step 4: 队列语义对齐**

剧集详情页点某集仍传整季作为队列(**既有测试守着,不得破坏**)。
首页分区点开剧集时,连播应跟着剧走 —— 决定队列该怎么构造并在报告中说明取舍:
是把队列换成本剧集序,还是让连播逻辑不依赖队列。**两者选一,不要两套并存。**

- [ ] **Step 5: 端到端验证**

用端到端脚手架播一集接近结尾的剧集,断言自动切到的是**本剧下一集**。
条目从服务器动态挑选,**不得把条目 id 或剧名写死进代码/提交信息/报告**。

- [ ] **Step 6: Commit**:`fix(player): follow the series order when auto-advancing`
