# 播放稳定性、浏览层对齐与系统集成 设计文档

> 状态:已定稿(2026-07-27)
> 前置:v1(`2026-07-25-jellycast-design.md`)与 v1.1 分页搜索(`2026-07-26-…`)已合入 master。

---

## 1. 为什么做这个

v1 在真机上第一次被完整使用,结论是**不可用**:

> 「播放的时候非常不稳定,经常闪退,不播放,还不如 web mobile」

用户确认四个环节**全部**出问题:开始播放的瞬间、播放中途、锁屏/切后台、seek 与切集。
四个全中说明这不是四个独立缺陷,而是地基上有系统性问题。

同时提出两项体验要求:浏览层向 Jellyfin Web mobile 看齐;补上应用图标与 OPPO 流体云。

**优先级由用户明确指定:能真正稳定播放 > 一切。** UI 与系统集成排在稳定性之后。

---

## 2. 目标与非目标

**做:**
- 建立可重复的**真机级自动化验证**(这是前提,不是附属品)
- 播放稳定性根因修复
- 浏览层对齐 Jellyfin Web mobile(**保持浅色主题**)
- 应用图标
- 系统媒体通知规范化 → OPPO 流体云 / 锁屏 / 蓝牙

**不做:**
- **不改播放页形态。** 仍是大封面 + 歌词式字幕,这是产品身份(用户明确选择"浏览层对齐,播放页保持播客形态")。
- **不改深色主题。** 用户明确要求保持浅色,尽管 Web mobile 是深色。
- 不接 OPPO 私有 SDK(需厂商权限;流体云对媒体场景走标准 MediaSession)。
- 不做离线下载、投屏、收藏夹。

## 3. 第一部分:可重复的真机级验证(前提)

### 3.1 为什么这一条排在最前

v1 至今**没有任何一次端到端验证**。281 个单测全绿,却在真机上四个环节全崩 —— 因为单测跑在 JVM 上,没有 StrictMode、没有真实 IME、没有前台服务限制、没有 TCP 分段时序。

已经有两个 bug 证明了这一点:`Response.close()` 在主线程排空 socket(依赖 TCP 分段时序),以及软键盘篡改密码(依赖真实 IME)。**手工点击不可重复、覆盖不到时序,而且我此前正是因为点不动才全部漏掉。**

### 3.2 手段:Hilt 仪器测试 + 真实服务器

在 `:app/src/androidTest` 建端到端测试,用 Hilt 测试替换预置服务器配置(**跳过登录表单**这个自动化卡点),其余全部走真实链路:真 `ExoPlayer`、真 `MediaSessionService`、真 Jellyfin。

**断言必须是行为性的,不是"没抛异常"。** 例如"播放位置在 10 秒内确实前进了 ≥5 秒",而不是"调用没报错"。

### 3.3 ⚠️ 凭据处理(硬约束)

测试需要真实服务器与账号。**绝对约束:**

- 服务器地址、用户名、密码**一律不得出现在代码、测试、文档、提交信息、日志或任何报告中**
- 从**已被 gitignore 的本地文件**读取(如 `local.properties` 或 `testing.properties`),文件本身不提交
- 提交模板 `testing.properties.example`,只含占位符
- 配置缺失时,端到端测试**跳过(skip)而不是失败**,这样别人 clone 下来 CI 不红
- 每个 Task 验收时必须执行一次泄漏复查:`git ls-files` + 全历史 grep

### 3.4 覆盖面(对应用户报告的四个环节)

| 场景 | 断言 |
|---|---|
| 开始播放 | 前台服务在系统限时内起来;位置开始前进 |
| 持续播放 | 连续 30 秒不中断、不崩 |
| 锁屏 / 切后台 | 进程存活,播放继续,通知在 |
| seek / 快进 / 切集 | 位置跳到目标附近并继续前进,不崩 |

## 4. 第二部分:稳定性根因修复

### 4.1 首要嫌疑(来自此前被判为"可接受取舍"的遗留项)

四个症状全中,说明这些判断是错的:

| 遗留项 | 可能对应的症状 |
|---|---|
| `startForegroundService` 在 `PlaybackInfo` + 探测两次网络往返**之前**调用;超过系统 5 秒限时抛 `ForegroundServiceDidNotStartInTimeException` | 点击播放瞬间闪退 |
| `HttpStreamProbe` 每次 `resolve()` 发一次完整 GET,**每次 seek 都在 NAS 上起一个新转码**并随即丢弃 | seek/快进卡死、服务端资源耗尽 |
| `TrustAwareHttpClientModule` 在 Hilt provider 里 `runBlocking` 读 DataStore | 主线程阻塞 → ANR |
| 自动连播时 `resolve()` 被调用两次 | 切集异常 |

**这些是嫌疑,不是结论。** 一律先复现、拿到真实堆栈,再按 systematic-debugging 定位,不猜着改。

### 4.2 纪律

- 每个缺陷必须先有**能复现它的失败测试**,再改
- 改完必须由该测试从红转绿证明
- 修复不得削弱既有保证:首个成功探测胜出、落选探测真取消、`CancellationException` 传播、
  L3 恒可播、字幕失败不影响播放、seek 走重新 resolve、TLS 不放宽

## 5. 第三部分:浏览层对齐 Jellyfin Web mobile

**保持浅色主题。** 参照的是**结构与信息层级**,不是配色。

| 项 | 现状 | 目标 |
|---|---|---|
| 顶部 | 无 | 应用标识 + 搜索 + 账号入口;下方「首页 / 我的最爱」标签 |
| **我的媒体** | **缺失** | 库入口卡片(电视剧 / 电影 / 动漫 / 纪录片…),走 `GET /UserViews` |
| 继续收听 | 竖版海报 | **16:9 缩略图** + 底部已听进度条 + 播放三角浮层 |
| 最近添加 | 单一平铺 | 按库分组(「最近添加的 电视剧」),标题右侧 `>` 进入该库 |
| 角标 | 无 | 未看集数角标 |

接口一律以 `docs/jellyfin-openapi.json` 为准。**Jellyfin 对错误大小写的查询参数静默忽略**,
v1 期间已查出 6 处此类错误,必须逐个 `jq` 核对。

「我的最爱」标签本次**只建结构不实现内容**(收藏在 v1 非目标内),显示占位或直接隐藏 ——
避免做一个点进去是空的假入口。

## 6. 第四部分:图标与系统集成

### 6.1 应用图标

现在用的是默认图标。需要自适应图标(前景 / 背景分层),覆盖各密度与圆形/方形/带圆角遮罩。
视觉方向:呼应产品是"把剧当播客听" —— 音频与播放的意象,而非视频。矢量实现,不用位图。

### 6.2 媒体通知规范化(流体云 / 锁屏 / 蓝牙的共同前提)

OPPO ColorOS 的**流体云对媒体场景是接管标准 MediaSession 通知**的(小宇宙同理),
不需要厂商私有 SDK。所以要做的是把元数据与通知做规范:

- 给 ExoPlayer 的 `MediaItem` 设完整 `MediaMetadata`:标题、副标题(剧名 · SxxExx)、
  **封面**(`artworkUri` 或 `artworkData`)
- 确认前台通知是 Media 样式、携带 session token、通道配置正确
- 确认锁屏显示封面与进度

> ⚠️ **待验证的怀疑:** 当前很可能**从未给 MediaItem 设过 metadata**,那样锁屏与流体云
> 只会显示空白或包名。这一点在实现前先确认。

流体云本身**只能在真机上验收**,模拟器没有 ColorOS。测试覆盖到"通知内容正确"为止,
流体云表现列为用户手工验收项,**不得伪造结果**。

---

## 7. 验收标准

**稳定性(硬门槛,不达标不算完成):**
- 用户报告的四个环节,每个都有自动化测试覆盖并通过
- 连续播放 30 秒不中断
- seek / 快进 / 切集不崩

**浏览层:** 首页结构与截图一致(浅色);「我的媒体」可进入各库。

**系统集成:** 锁屏与通知显示正确的标题、副标题、封面;图标在桌面正常显示。

**纪律:** 任何真实凭据不得出现在仓库任何位置(含历史)。
