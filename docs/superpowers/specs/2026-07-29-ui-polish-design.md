# 播放页可读性、首页布局与服务器管理 设计文档

> 状态:已定稿(2026-07-29)
> 前置:v4(崩溃修复与功能可用性)已合入 `feat/stability-and-web-parity`。
> 本文覆盖真机使用后暴露的四个界面/功能问题。

---

## 1. 为什么做这个

App 现在能正常播放了,问题从"能不能用"转成了"好不好用"。用户在真机上提出四点:

1. **播放页的当前字幕被遮挡看不见** —— 歌词区被压到只剩两行,当前行经常被裁掉。
   这是产品的招牌功能,不可读等于没有。
2. **首页顶部有一大块空白** —— 状态栏高度被重复计算。
3. **首页没有下拉刷新** —— 想手动刷新只能杀进程重进。
4. **服务器管理不能删除服务器** —— 加错了地址就永远留在列表里。用户指出
   VidHub、Findroid 都有这个功能。

---

## 2. 各问题的根因

### 2.1 歌词区被挤压(核心问题)

`PlayerScreen` 是一个自上而下的 `Column`:折叠按钮 → 大封面 → 标题 → 副标题 →
**歌词区** → 进度条 → 时间 → 控制行 → 工具栏。歌词区拿的是 `Modifier.weight(1f)`,
即"其余元素排完之后的剩余空间"。

在实际机型上,封面(正方形、接近满宽)加上下方五组控件之后,留给歌词的只剩约两行的高度。
雪上加霜的是 `LyricsView` 用 `contentPadding = PaddingValues(vertical = halfViewport)`
把上下各垫掉半个视口 —— 视口本就很矮时,可视区域进一步塌缩,当前行落在边缘被裁。

**方向:** 让歌词区获得与其地位相称的空间。可选路径:

- 缩小封面,给歌词让位
- 播放中自动把封面收成小尺寸(类似音乐 App 的"迷你封面"态),歌词占主区
- 歌词区可展开/收起,或整页可滚动

**取舍:** 大封面是"感觉像播客"的关键视觉(v1 设计文档 §6 明确),不能简单砍掉。
但**当前行必须始终完整可见** —— 这是硬要求,优先于封面尺寸。
具体形态实现时定,但必须满足:任意时刻当前行完整可见,且上下至少各有一行上下文。

### 2.2 首页顶部空白:状态栏 inset 被算两次

`HomeScreen` 用的是 Material3 `TopAppBar`,它默认会应用 `TopAppBarDefaults.windowInsets`
(含状态栏)。而外层 `Scaffold` 也会把系统栏 inset 计入内容内边距。两者叠加,
顶部就多出约一个状态栏的高度。

**方向:** 让 inset 只被消费一次。要么由 `Scaffold` 统一处理、`TopAppBar` 覆写为不消费,
要么反过来。**实现时需在真机截图确认**,因为这类问题在不同刘海/挖孔屏上表现不同。

### 2.3 缺下拉刷新

列表已经是"缓存优先 + 后台刷新"(v3),但用户没有**主动**触发刷新的手段。
缓存策略保证了打开就有内容,却也意味着用户无法确认"这是不是最新的"。

**方向:** 首页与媒体库加下拉刷新,复用既有的仓储刷新路径,不要另起一套取数逻辑。
刷新失败时沿用既有的离线提示,不弹窗打断。

### 2.4 不能删除服务器

`ServerStore.delete(id)` 在 v1 就实现了,**UI 层从未接入**。

**方向:** 服务器列表项提供删除入口,**必须二次确认** —— 误删会丢掉登录态。
删除当前活跃服务器时要处理好后续状态:清掉活跃标记,并把该服务器的缓存一并清除
(`CachedItemDao.clearServer` 已存在),否则会留下无主的缓存数据。

若删除的是最后一台服务器,应回到"还没有添加服务器"的空状态。

---

## 3. 范围

**做:** 歌词可读性 · 首页 inset 修正 · 首页与媒体库下拉刷新 · 删除服务器(含二次确认与缓存清理)

**不做:**
- 深色主题(用户已明确否决)
- 改播放页的产品形态(仍是封面 + 歌词,不引入视频画面)
- 弹幕渲染

---

## 4. 测试策略

- **歌词可读性**:纯逻辑部分(当前行索引、可见行计算)走 JVM 单测;
  **布局必须有真机截图为证** —— 这类问题单测测不出来,本项目已有先例
  (v3 的离线提示条"存在但被挤出可视区"就是靠真机截图才发现的)。
- **inset**:同样以真机截图为准。
- **下拉刷新**:Compose UI 测试断言手势触发刷新;JVM 测试断言刷新走的是既有仓储路径。
- **删除服务器**:JVM 测试覆盖"确认后才删除""删除活跃服务器会清活跃标记与缓存"
  "删到空列表回到空状态";UI 测试覆盖二次确认对话框。

**新增铁律的延续:** 依赖平台行为的部分必须在真机上跑过 —— v4 的崩溃就是 JVM 测试
结构上测不出平台差异导致的。

---

## 5. 验收标准

- 播放中任意时刻**当前字幕行完整可见**,且上下至少各有一行上下文
- 首页顶部无多余空白(真机截图确认)
- 首页与媒体库可下拉刷新,失败时不弹窗、沿用离线提示
- 服务器可删除,有二次确认;删除后活跃标记与该服务器缓存一并清理;删空回到空状态
- 全部既有测试保持绿
